# 新电脑本地部署与测试（Windows，第一次）

在一台新的 Windows 电脑上拉取代码后，从源码把前后端跑起来、在系统页面上测试诊断。
不需要打包、不需要安装 Nginx。命令都在 **PowerShell** 中执行，除特别说明外都在**仓库根目录**下执行。

> PowerShell 运行当前目录里的 `.bat`、`.ps1` 时要在前面加 `.\`，例如 `.\测试实时诊断.bat`。

---

## 一、安装软件（只做一次）

需要三个软件：

| 软件 | 版本 | 用途 |
|---|---|---|
| Git | 任意 | 拉取代码 |
| Python | **3.11** | 后端 |
| Node.js | **18**（18.20.8） | 前端（vue-cli 4 在 18 上验证过，更新的版本可能编译不过） |

先打开 PowerShell 检查是否已经装过，已经有且版本对的可以跳过：

```powershell
git --version
python --version      # 应为 Python 3.11.x
node --version        # 应为 v18.x
```

下面两种安装方式任选一种。安装完成后**关掉 PowerShell 重新打开**（让新加的 PATH 生效），再用上面三条命令检查。

### 方式 A：用 winget 安装（Windows 10 1809 以上 / Windows 11 自带）

```powershell
winget install -e --id Git.Git
winget install -e --id Python.Python.3.11
winget install -e --id OpenJS.NodeJS --version 18.20.8
```

第一次使用 winget 会提示同意协议，输入 `Y` 回车。提示找不到 `winget` 或下载很慢时，用方式 B。
Node.js 如果提示找不到 18.20.8 这个版本，单独用方式 B 的第 3 条安装 Node.js。

### 方式 B：从国内镜像下载安装包，静默安装（不需要 winget）

用**管理员身份**打开 PowerShell（开始菜单右键 PowerShell →“以管理员身份运行”），逐段复制执行：

```powershell
$ProgressPreference = "SilentlyContinue"     # 关掉进度条，下载快很多
mkdir $env:TEMPench-setup -Force | Out-Null; cd $env:TEMPench-setup

# 1. Git
Invoke-WebRequest "https://mirrors.huaweicloud.com/git-for-windows/v2.47.1.windows.1/Git-2.47.1-64-bit.exe" -OutFile git.exe
Start-Process .\git.exe -ArgumentList "/VERYSILENT /NORESTART" -Wait

# 2. Python 3.11（加入 PATH，含 pip）
Invoke-WebRequest "https://mirrors.huaweicloud.com/python/3.11.9/python-3.11.9-amd64.exe" -OutFile python.exe
Start-Process .\python.exe -ArgumentList "/quiet InstallAllUsers=1 PrependPath=1 Include_test=0" -Wait

# 3. Node.js 18
Invoke-WebRequest "https://npmmirror.com/mirrors/node/v18.20.8/node-v18.20.8-x64.msi" -OutFile node.msi
Start-Process msiexec.exe -ArgumentList "/i node.msi /qn" -Wait
```

某个地址下载失败时，可以换成官网地址（较慢）：
Git `https://github.com/git-for-windows/git/releases/download/v2.47.1.windows.1/Git-2.47.1-64-bit.exe`、
Python `https://www.python.org/ftp/python/3.11.9/python-3.11.9-amd64.exe`、
Node.js `https://nodejs.org/dist/v18.20.8/node-v18.20.8-x64.msi`。
也可以把地址粘到浏览器里下载，双击安装（Python 安装第一页务必勾选 **Add python.exe to PATH**）。

### 方式 C：Node.js 不装到系统（可选）

不想在系统里装 Node.js 时，拉取代码后在仓库根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File deploy\windows\get_tools.ps1
```

它把免安装版 Node.js 下载到 `deploy\windows\tools\node`（同时下载打包用的 Inno Setup）。之后每个要用 `npm` 的窗口先执行：

```powershell
$env:Path = "$PWD\deploy\windows\tools\node;$env:Path"   # 在仓库根目录执行
```

### 设置国内镜像（推荐，只做一次）

之后安装 Python 包、前端依赖都走国内镜像，速度快很多：

```powershell
python -m pip install --upgrade pip -i https://mirrors.aliyun.com/pypi/simple/
pip config set global.index-url https://mirrors.aliyun.com/pypi/simple/
npm config set registry https://registry.npmmirror.com
```

### 允许运行本地脚本（只做一次）

激活 Python 虚拟环境、运行项目里的 `.ps1` 需要：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned      # 提示时输入 Y 回车
```

## 三、配置 `.env`（只做一次）

```powershell
copy .env.example .env
python -c "import secrets; print(secrets.token_hex(32))"     # 生成一串随机字符，作为 SECRET_KEY
notepad .env
```

在记事本中填写两项后保存：

```
SECRET_KEY=上面生成的那串字符
ADMIN_PASSWORD=你的登录密码
```

其余保持默认即可（登录用户名 `admin`，统一入口端口 8080）。

## 四、安装后端依赖（只做一次）

任选一种：

```powershell
# 方式 1：直接用系统 Python（推荐使用虚拟环境，避免影响其他项目）
python -m venv .venv
.\.venv\Scripts\Activate.ps1          # 激活后命令行前面会出现 (.venv)
pip install -r pump_test_bench\requirements.txt

# 方式 2：conda（需先安装 Miniconda：winget install -e --id Anaconda.Miniconda3，装完重新打开 PowerShell 并执行 conda init powershell）
conda env create -f pump_test_bench\environment.yml
conda activate backend503
```

> 用虚拟环境/conda 时，以后每次新开窗口启动后端前，都要先执行激活命令（`.\.venv\Scripts\Activate.ps1` 或 `conda activate backend503`）。

验证后端代码（约 1 分钟，应全部通过）：

```powershell
python -m pytest -q pump_test_bench\tests
```

## 六、启动系统（每次测试）

需要两个窗口，测试期间都不要关。

**窗口 1：后端**（仓库根目录；用了虚拟环境/conda 的先激活）

```powershell
python -m pump_test_bench.app.services.supervisor
```

看到 `系统已启动` 以及 `已启动 task_service`、`已启动 file_service` 即可。

**窗口 2：前端**（用方式 C 准备 Node 的先执行上面的 `$env:Path = ...`）

```powershell
cd digital-twin-platform
$env:NODE_OPTIONS = "--openssl-legacy-provider"
npm run dev
```

等出现 `App running at: - Local: http://localhost:9528/`（第一次编译约 1–2 分钟）。

**浏览器打开 http://localhost:9528**，用户名 `admin`，密码是 `.env` 里的 `ADMIN_PASSWORD`。

> 也可以不开前端开发服务：先在 `digital-twin-platform` 下执行一次 `npm run build:prod`，之后只开窗口 1，打开 http://localhost:8080 。
> 这种方式改了前端代码要重新 build 才生效；开发、调试时用 9528 的方式（改代码后页面自动刷新）。

## 七、在系统页面上测试诊断

### 1. 模拟试验台实时产出数据

新开第三个窗口，在仓库根目录：

```powershell
python -m pump_test_bench.tools.simulate_live_data --cases F20,F21,F22,F23,F11,F19 --speed 2
```

（等价于 `.\测试实时诊断.bat --cases F20,F21,F22,F23,F11,F19 --speed 2`）

脚本会在正常数据上注入故障生成数据文件，然后显示：

```
写入目录：...\live_test_data\<时间>\data
数据清单：...\live_test_data\<时间>\data_数据清单.csv
设置好后按回车开始写入
```

### 2. 在系统里设置数据目录

工作台 → **设置数据目录** → 粘贴上面的“写入目录”完整路径 → 勾选 **文件写完后自动诊断** → 保存。

### 3. 开始写入并观察

回到脚本窗口按回车。脚本逐个文件按时间一行一行写入：

- 工作台：实时曲线在动、三维模型上的数值在变；
- 每个文件写完约 3 秒后自动诊断：工作台出现最新结论，“诊断记录”里多一条来源为“自动诊断”的记录；
- 打开 `数据清单.csv`，逐个对照预期结论（见 `docs\实时诊断测试说明.md` 的对照表）。

### 4. 其他测试方式

| 想测什么 | 命令 |
|---|---|
| 默认一轮（2 个正常 + 7 类典型故障），确认正常数据不误报 | `python -m pump_test_bench.tools.simulate_live_data` |
| 全部故障用例（约 56 个文件） | `python -m pump_test_bench.tools.simulate_live_data --cases all --speed 4` |
| 先生成故障数据文件，再回放其中某一类 | `python -m pump_test_bench.tools.generate_fault_data "标准台性能录取数据\标准台性能录取数据" --out 故障数据`<br>`python -m pump_test_bench.tools.simulate_live_data --source 故障数据\F22_中途突发偏低 --speed 2` |
| 回放自己的数据文件 | `python -m pump_test_bench.tools.simulate_live_data --source D:\我的数据` |
| 不等回车、写到指定目录 | 加 `--no-wait --to D:\实时数据` |
| 不开系统，只看算法结果（54 个故障文件与预期对照） | `python -m pump_test_bench.tools.generate_fault_data "标准台性能录取数据\标准台性能录取数据" --out 故障数据` |

也可以不用实时写入：在“自动诊断”页填写数据目录，选择文件批量诊断。

## 九、常见问题

| 现象 | 处理 |
|---|---|
| `'xxx.bat' is not recognized` | PowerShell 中要写 `.\xxx.bat` |
| 启动后端提示未找到 `.env` / 登录失败 | 检查第三步，`SECRET_KEY`、`ADMIN_PASSWORD` 都要填；改了 `.env` 要重启后端 |
| 端口被占用（5001、5002、8080） | `netstat -ano \| findstr LISTENING \| findstr ":5001 :5002 :8080"` 查到占用的进程号，在任务管理器中结束；本机装过安装版时先 `schtasks /End /TN BenchCheck`（管理员） |
| `npm run dev` 报 `digital envelope routines::unsupported` | 没设 `$env:NODE_OPTIONS = "--openssl-legacy-provider"`（每个新窗口都要设） |
| `git` / `python` / `npm` 不是命令 | 没装，或装完没有重新打开 PowerShell；用方式 C 准备 Node 时没在本窗口执行 `$env:Path = ...` |
| `python` 打开了微软商店 | Windows 自带的“应用执行别名”：设置 → 应用 → 高级应用设置 → 应用执行别名，关掉 python.exe 和 python3.exe，再重新打开 PowerShell |
| 激活虚拟环境提示“禁止运行脚本” | 执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| `pip install` / `npm ci` 很慢或超时 | 执行第一节“设置国内镜像”的三条命令后重试 |
| 页面显示正常但接口报错 | 看窗口 1 的输出和 `logs\` 下的日志 |
| 文件写完一直不出结论 | 确认勾选了“文件写完后自动诊断”，且填写的目录与脚本的写入目录完全一致 |
| 资源管理器里正在写的文件显示 0 KB | Windows 在文件写完关闭前不刷新大小，用记事本打开可以看到内容，属正常 |

## 十、改完代码后

- 后端代码改动：窗口 1 按 Ctrl+C 后重新运行 `python -m pump_test_bench.app.services.supervisor`；
- 前端代码改动：`npm run dev` 会自动刷新页面；
- 提交前运行 `python -m pytest -q pump_test_bench\tests`；
- 需要生成安装包时：关掉以上窗口，运行 `.\打包安装包.bat`（见 `deploy\windows\README.md`）。
