# 实时故障诊断测试：模拟试验台实时产出数据

`测试实时诊断.bat` 模拟试验台：按数据里的时间，把数据文件**一行一行地写进一个目录**（边测边写）。
写入的数据有两类：正常数据，以及在正常数据上注入了故障的数据。脚本只负责产出数据，
实时曲线和诊断结论在系统页面上查看，对照脚本生成的 **数据清单.csv**（每个文件注入了什么故障、预期结论）判断对不对。

## 一、测试步骤

1. **确认系统在运行**（安装版开机自动运行；开发环境运行 `python -m pump_test_bench.app.services.supervisor`），用浏览器登录系统。
2. **双击仓库根目录的 `测试实时诊断.bat`**。它先准备好数据文件，然后显示：
   ```
   写入目录：C:\...\shiyantai-new\live_test_data\20261112-172500\data
   数据清单：C:\...\shiyantai-new\live_test_data\20261112-172500\data_数据清单.csv
   请在系统“工作台 → 数据目录”中填写上面的写入目录，并打开“自动诊断”……
   设置好后按回车开始写入
   ```
3. **在系统里设置**：工作台 → 数据目录，填写上面的“写入目录”（复制粘贴完整路径），并打开“自动诊断”。
4. **回到脚本窗口按回车**，开始逐个写入文件。窗口里会显示正在写哪个文件、注入的是什么故障、预期结论。
5. **在系统页面上看**：
   - 工作台：写入过程中实时曲线在动、三维模型上的数值在变；
   - 每个文件写完（停止写入约 3 秒后）系统自动诊断：工作台上出现最新结论，“诊断记录”里出现一条来源为“自动诊断”的记录；
   - 打开 `数据清单.csv`，逐个对照诊断结论与预期结论。
6. 全部写完后脚本结束；测试完成后记得把工作台的数据目录改回实际的数据目录。

## 二、写哪些数据

默认（快速）：共 9 个文件，按真实速度约 8 分钟：

- 2 个正常文件（预期：正常，不应报警）；
- 7 类典型故障各 1 个：涡轮流量计磨损、叶轮卡滞冻结、断线归零、供回油泄漏、油温传感器偏移、被试泵出力下降、压力传感器零漂。

| 参数 | 作用 |
|---|---|
| `--cases all` | 全部故障用例（约 50 个文件） |
| `--cases F01,F11,F16` | 只写指定故障编号的文件（编号见 `pump_test_bench/tools/generate_fault_data.py`） |
| `--source D:\我的数据` | 回放自己准备的数据文件（含子目录）。是 `generate_fault_data` 生成的故障数据目录（或其中某个故障子目录）时，从 `故障清单.csv` 读出预期结论 |
| `--to D:\实时数据` | 写到指定目录（默认仓库下 `live_test_data\<时间>\data`） |
| `--speed 4` | 写入倍速，默认 1（真实速度，每个文件 30–40 秒） |
| `--gap 15` | 两个文件之间停顿的秒数，默认 15（留时间给系统诊断） |
| `--loop` | 写完一轮从头再来（长时间运行测试） |
| `--no-wait` | 不等回车，直接开始写入 |

例如在命令行运行：`测试实时诊断.bat --cases all --speed 4`。

全部故障的机理、受影响的测点和注入规律见仓库根目录 `故障注入数据/故障注入清单.md`（编号 F01–F35，该目录就是一组已生成好的故障数据，
可以直接回放：`测试实时诊断.bat --source 故障注入数据 --speed 4`）。

诊断算法 3.0 新增的判断（故障隔离、变点检测）可以用下面的用例专门测试：

```
测试实时诊断.bat --cases F20,F21,F22,F23,F11,F19 --speed 2
```

| 编号 | 注入的故障 | 预期诊断 |
|---|---|---|
| F20 | 三只供油侧流量计同时偏高 3% | 供油侧流量计整体偏高（不是泄漏） |
| F21 | 全部体积流量计同时偏低 3% | 体积流量计整体偏低（不是质量流量计漂移） |
| F22 | 回油流量1-2 在测试一半时突然偏低 4% | 回油流量1-2 计量偏差（中途突变），说明里给出变化开始的秒数 |
| F23 | 回油流量1-1、供油流量1-1 同时偏低 3% | 只报这两只表，其余表正常 |
| F11 | 供回油之间泄漏 | 供回油之间泄漏 |
| F19 | 两只回油流量计同时偏低 4% | 两只回油流量计同时偏低 |

## 三、预期结论怎么对照

`数据清单.csv` 每一行是一个写入的文件：序号、文件名、数据（注入的故障与程度）、预期结论（正常 / 预警 / 异常）、预期诊断。
文件名以序号开头，与“诊断记录”中的文件名一一对应。

- 实际结论与预期一致：正常；
- 预期“预警”、实际“异常”：比预期更敏感，一般可以接受；
- 正常文件报了预警/异常（误报），或故障文件判为正常（漏报）：打开该记录的报告查看原因。

## 四、注意

- 系统要能读到写入目录：写入目录需在运行系统的电脑上（或系统能访问的共享目录）。
- 默认的故障数据由仓库里的正常数据（`标准台性能录取数据\标准台性能录取数据`）生成；在没有这份数据的电脑上，
  用 `--healthy 目录` 指定，或用 `--source` 回放自己的数据。
- 中途按 Ctrl+C 停止写入。
