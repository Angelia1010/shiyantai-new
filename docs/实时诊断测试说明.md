# 实时故障诊断测试

用来检查“试验台边测边写数据 → 系统实时显示 → 文件写完自动诊断 → 诊断结论正确”这条完整链路。
测试脚本模拟试验台：把数据文件按时间一行一行写进被监控的目录，再通过网页同样的接口检查每一步，
不直接调用诊断代码，所以测出来的就是用户实际看到的效果。

## 一、怎么运行

**前提**：系统已经在本机运行。

- 安装版：开机自动运行；没运行时用开始菜单“标准台校验系统 → 启动服务”。
- 开发环境：在仓库根目录运行 `python -m pump_test_bench.app.services.supervisor`（统一入口 http://localhost:8080）。

**运行**：双击仓库根目录的 **`测试实时诊断.bat`**，按提示输入登录密码。

快速测试约 2–3 分钟：2 个正常文件 + 7 类典型故障（涡轮磨损、叶轮卡滞、断线、泄漏、油温传感器偏移、被试泵出力下降、压力传感器零漂）。

也可以在命令行带参数运行：

```bat
测试实时诊断.bat --cases all                 :: 全部故障用例（约 50 个，10 分钟左右）
测试实时诊断.bat --cases F01,F11,F16         :: 只测指定的故障编号
测试实时诊断.bat --source D:\我的数据         :: 回放自己准备的数据文件（没有预期结论，只记录诊断结果）
测试实时诊断.bat --speed 1                   :: 按真实速度写入（每个文件 30–40 秒），默认 4 倍速
测试实时诊断.bat --url http://localhost:9528 :: 开发时用前端开发服务的地址
测试实时诊断.bat --password 你的密码          :: 不再提示输入密码
```

`测试实时诊断.bat` 会自动选用 Python：先用已安装系统自带的（`C:\Program Files\BenchCheck\python`），
其次用打包目录里的，最后用命令行里的 `python`（开发环境需先激活 conda 环境）。
也可以直接运行 `python -m pump_test_bench.tools.live_diagnosis_test ...`。

## 二、测试过程

1. 登录系统；
2. 在正常数据上注入故障，生成测试用例（与 `generate_fault_data` 相同的故障与预期结论）；
3. 把系统的监控目录临时切换到测试目录（`live_test_runs\<时间>\watch`），并开启自动诊断；
4. 逐个用例：
   - 按时间把数据一行一行写入测试目录（模拟试验台边测边写）；
   - 写入过程中检查系统是否在实时显示这个文件的数据（工作台看到的实时数据）；
   - 文件写完后，等待系统自动诊断（最多 120 秒），读取诊断报告；
   - 对比实际结论与预期结论；
5. 恢复原来的监控目录与自动诊断设置，输出汇总与报告。

## 三、怎么看结果

控制台逐个显示，最后一行是汇总，例如：

```
==== 通过 9，偏严 0，不符 0，超时 0，失败 0；实时显示正常 9/9；文件写完到出结果平均 3.7 秒 ====
```

| 判定 | 含义 | 处理 |
|---|---|---|
| 通过 | 实际结论与预期一致 | — |
| 偏严 | 预期“预警”、实际“异常”：比预期更敏感 | 一般可以接受；如果太敏感，调大仿真模型诊断方案的倍数 |
| 不符 | 结论与预期不一致（漏报或误报） | 查看报告中的“实际诊断”，必要时在系统里打开该任务的报告分析 |
| 超时 | 文件写完后 120 秒内没有诊断结果 | 看说明：“没有创建诊断任务”多半是自动诊断没开或监控目录不对；查看日志 `file_service.log` |
| 失败 | 写文件出错或诊断出错 | 看说明与日志 |
| 实时显示 = 否 | 写入过程中系统没有显示这个文件的实时数据 | 查看 `file_service.log`；确认测试目录能被系统读到 |

报告保存在测试目录下（默认 `live_test_runs\<时间>\`）：

- `实时诊断测试报告.csv`：每个用例的预期、实际结论与诊断、是否实时显示、写入与诊断耗时、任务编号；
- `实时诊断测试报告.md`：同样内容的表格，方便贴到文档里。

测试中的诊断任务会出现在系统的“诊断记录”里（来源为自动诊断），可以逐个打开查看完整报告。
全部符合预期时脚本退出码为 0，可以用于升级后的回归检查。

## 四、注意

- 测试期间系统的监控目录会临时切换到测试目录，结束后自动恢复。中途关闭窗口时，请到工作台“数据目录”重新设置。
- 被测系统需要在本机：测试目录要能被系统读到。
- 正常数据默认取仓库里的 `标准台性能录取数据\标准台性能录取数据`；在没有这份数据的电脑上，用 `--healthy 目录` 指定，
  或用 `--source` 回放自己的数据。
- 本机自测结果（10 倍速）：正常 2 个 + 涡轮磨损、泄漏、被试泵出力下降、压力零漂共 19 个用例全部通过，
  实时显示全部正常，文件写完到出诊断结果约 4 秒。
