# 扩展指南：代理模型构建方法、仿真引擎、诊断插件

本系统按“核心流程不动、在固定接口上加实现”的方式组织。下表是可以扩展的位置，每一种都不需要改动诊断引擎、标定或前端主体。

| 想加的东西 | 接口 | 注册方式 | 前端 |
|---|---|---|---|
| 新的数据拟合方法（如基于大模型分析数据、提出公式） | `simulation/builders/base.py` 的 `SurrogateBuilder` | `builders.register(...)` | `user_selectable` 为真时，编辑页“计算方式”自动列出，选项按 `options` 生成 |
| 新的仿真软件（如 Simulink、FMU、自研求解器） | `simulation/models.py` 的 `SimulationModel` | `register_engine(...)` | 模型方式中可选 |
| 新的模型产物类型（非网格、非公式） | `simulation/table.py` 的 `PREDICTORS` | 字典中加一项 | 无需改动 |
| 新的诊断检查（参与结论） | `diagnosis/plugins.py` 的 `Analyzer` | `register_analyzer(...)` | 发现与原因按现有方式显示 |
| 结论之后的独立分析（如大模型智能体） | `diagnosis/plugins.py` 的 `Reasoner` | `register_reasoner(...)` | 报告中“扩展分析意见”一栏（`components/ReviewList`），Word 报告附在最后 |

插件模块的加载：在 `pump_test_bench/config/plugins.json` 的 `modules` 中列出模块名（或设环境变量 `DIAGNOSIS_PLUGINS`，逗号分隔），
服务启动后第一次用到时导入（构建器、诊断插件都可以写在这些模块里）；`disabled` 列出暂时停用的插件名，`options` 给各插件传选项。插件出错或超时只记录在报告中，不影响诊断。

## 1. 整体结构

```
采集数据 ─┬─ diagnosis/engine.analyze ── 内置检查（互校、泄漏、质量-体积、传感器自检、模型残差）
          │        └─ plugins.run_analyzers ── 扩展分析器（发现参与结论）
          ├─ causes.infer_causes ── 原因推断 → 结论
          └─ plugins.run_reasoners ── 扩展推理器（如大模型智能体），独立意见 report["reviews"]

仿真模型（健康参考模型）
  config.py      模型配置（变量、输出、计算方式、规则、阈值）与校验
  condition.py   从稳定段取变量（测点、多测点中位数、由油温算密度/黏度、常数，再做单位换算）
  builders/      数据代理模型的构建器：autofit（按变量角色定结构）、formula（内置公式，仅后端配置）…
  surrogate.py   通用流程：拟合 → 留一组交叉验证 → 误差、异常样本、建议 → 公式产物
  formula.py     公式引擎：白名单解析、numpy 计算、系数拟合（LM）、多项式展开
  models.py      网格类仿真引擎（AMESim…），register_engine 注册
  table.py       模型产物：grid（插值）/ formula（直接计算），predict() 按 kind 分派
  calibration.py 用正常数据标定固有偏差与离散 σ（阈值依据）
  check.py       诊断时的模型残差检查（单测点偏离、整体偏移）
  service.py     对外接口的编排（不含算法）
```

模块之间只通过数据（配置 dict、样本 list、产物 dict）交互：构建器不知道标定和诊断，诊断不知道模型是怎么建的。

## 2. 新增一种代理模型构建方法

构建器只负责一件事：**给定一批正常数据，给出某个输出的公式和系数**。交叉验证、误差统计、异常样本、标定、诊断、页面展示都由通用代码完成。

```python
# my_plugins/llm_builder.py
import asyncio
import json

from pump_test_bench.app.llm.ollama_client import OllamaClient
from pump_test_bench.app.simulation.builders import FitResult, OptionSpec, SurrogateBuilder, get_builder, register
from pump_test_bench.app.simulation.builders.base import FitData


class LLMFormulaBuilder(SurrogateBuilder):
    kind = "llm"
    label = "大模型提出公式"
    description = "大模型阅读数据摘要与物理背景，提出公式形式；系数由数据拟合"
    options = [OptionSpec("hint", "物理背景提示", "text", "", help="如：涡轮流量计转速与体积流量成正比")]

    def fit(self, data: FitData) -> FitResult:
        # 1) 给大模型看数据摘要（不要整批原始数据）
        summary = {n: [float(v.min()), float(v.max())] for n, v in data.variables.items()}
        prompt = (f"变量范围：{json.dumps(summary, ensure_ascii=False)}；输出 {data.output['name']} 范围 "
                  f"[{data.y.min():.4g}, {data.y.max():.4g}]。{(data.output.get('llm') or {}).get('hint', '')}\n"
                  "请只回答一个 JSON：{\"expression\": 公式, \"coefficients\": {系数名: 初值}}。"
                  "公式只能用 + - * / ^ exp log sqrt 和上述变量名。")
        text = asyncio.run(OllamaClient().generate(prompt, max_tokens=400, temperature=0.2))
        proposal = json.loads(text[text.index("{"):text.rindex("}") + 1])
        # 2) 系数交给公式构建器（formula）拟合（公式会经过白名单解析，不会执行任意代码）
        spec = {"expression": proposal["expression"],
                "coefficients": {k: {"value": v, "fit": True} for k, v in proposal["coefficients"].items()}}
        formula = get_builder("formula")
        result = formula.fit(FitData(data.variables, data.y, data.groups, {**data.output, "formula": spec},
                                     data.inputs, data.files))
        # 3) 交叉验证时不要每一折都问大模型：给出 refit，只重估系数
        result.refit = {"method": "formula", **spec}
        result.info["proposed_by"] = "llm"
        return result

    def available(self) -> bool:
        return True  # 可检查 Ollama 是否在线


register(LLMFormulaBuilder())
```

把 `my_plugins.llm_builder` 加到 `config/plugins.json` 的 `modules` 中即可：第一次用到构建器（打开仿真模型页、保存或建立模型、诊断）时导入，
之后编辑页输出的“计算方式”中就有“大模型提出公式”，选项按 `options` 生成，结果与其他方式一样经过交叉验证、标定后参与诊断。

注意：
- 由数据提出结构的方法（如大模型看了数据再提公式）在交叉验证中会偏乐观，因为结构是看过全部数据后选的；
  `refit` 只重估系数，误差会略低于真实水平。需要严格评估时，在 `fit()` 中按 `data.groups` 自行做嵌套验证。
- 公式里的名字必须是变量名或系数名。构建器设 `user_selectable = False` 时只能在后端配置文件中使用（如内置公式），
  页面上不可选；接口不返回公式与系数，页面只显示精度。

## 4. 新增诊断检查（分析器）

```python
from pump_test_bench.app.diagnosis import plugins
from pump_test_bench.app.diagnosis.checks import ABNORMAL, WARNING, finding

class VibrationCheck(plugins.Analyzer):
    name, label = "vibration", "振动检查"

    def analyze(self, ctx):
        means = ctx.segment_means()                 # 稳定段均值
        limit = ctx.options.get("warn", 4.0)        # plugins.json 的 options.vibration.warn
        v = means.get("振动传感器1-1")
        if v is not None and v > limit:
            return [finding("vibration", WARNING, "振动偏大", f"振动传感器1-1 均值 {v:.2f}，超过 {limit}",
                            "振动传感器1-1", "振动传感器1-1", component="被试件1高低压双联泵", value=v)]
        return []

plugins.register_analyzer(VibrationCheck())
```

发现的 `severity` 为 warning / abnormal 时参与结论，归入原因分析（未知类别按测点归并为一条原因）；notice 只作补充。

## 5. 大模型智能体诊断（推理器）

推理器在规则结论之后运行，拿到完整报告与数据，给出独立意见；**不改变规则引擎的结论**，与之并列展示，由人判断。

```python
import asyncio, json
from pump_test_bench.app.diagnosis import plugins
from pump_test_bench.app.llm.ollama_client import OllamaClient

class LLMAgent(plugins.Reasoner):
    name, label = "llm_agent", "大模型智能体"
    timeout_s = 120

    def review(self, report, ctx):
        facts = {
            "结论": report["summary"],
            "原因": [{"名称": c["name"], "依据": c["evidence"]} for c in report["causes"]],
            "工况": report["condition"],
            "模型对比": [{"模型": m["name"], "偏离": [(r["column"], r["residual"]) for r in m["rows"]
                                                    if r.get("severity") != "info"]} for m in report["models"]],
        }
        # 智能体可以“调用工具”做推演，例如：转速提高 10% 时模型预期是多少
        cond = report["condition"]
        prompt = ("你是燃油泵试验台的诊断工程师。根据以下事实给出综合判断、需要追问的现象和处理建议，"
                  "只回答 JSON：{\"title\":..,\"summary\":..,\"details\":..,\"suggestions\":[..],\"confidence\":0-1}\n"
                  + json.dumps(facts, ensure_ascii=False))
        text = asyncio.run(OllamaClient().generate(prompt, max_tokens=800, temperature=0.2))
        return json.loads(text[text.index("{"):text.rindex("}") + 1])

plugins.register_reasoner(LLMAgent())
```

`ctx` 提供的“工具”：`ctx.segment_means()`（稳定段均值）、`ctx.model_expected(模型 id, 工况)`（用仿真模型推演任意工况）、
`ctx.analysis`（内置检查的全部中间结果）、`ctx.df`（原始数据）、`ctx.cfg`（诊断配置）。
多轮的智能体（反复调用工具、追问）可在 `review()` 内部实现循环；耗时较长时调大 `options.<名字>.timeout_s`。

返回字段：`title`、`summary`、`details`、`suggestions`（列表）、`references`（列表）、`confidence`（0–1），均可选。
